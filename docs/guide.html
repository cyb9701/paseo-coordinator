Coordinator 시스템 한눈에 보기

여러 워크스페이스의 에이전트 중 지금 나를 기다리는 일을 인박스 한곳에 카드로 모으고, 내 답을 에이전트가 쉴 때 전합니다. 일은 사람이 시작하고, 플러그인은 지켜보고 모으고 전달만 합니다.

코디네이터 세션·질문 찾기·요약 에이전트는 모두 ~/.paseo/plugin-data/paseo-coordinator/coordinator 워크스페이스 하나(프로젝트 coordinator)에서 돕니다. 질문 찾기·요약은 숨은(background) 에이전트이고 도구 없이 받은 글만 읽습니다. 코디네이터는 자기 도구 4개(read_sessions record_judgment answer_fact review_reports)만 쓸 수 있습니다.

3카드가 생기는 조건

카드만드는 쪽생기는 조건위치숫자
권한 요청 · 질문 창코드에이전트가 권한을 묻거나 질문 창(AskUserQuestion)을 띄움. 모든 프로젝트내 결정 필요요청마다 1
에러코드턴 실패. 모든 프로젝트내 결정 필요에이전트마다 1
멈춘 결정코드 + 요약record_decision 이 멈춤 규칙에 걸림 (아래 5)내 결정 필요에이전트마다 1
판정: question질문 찾기 / 코디네이터에이전트가 말로 사람에게 묻고 턴을 끝냄 (위 카드가 없을 때)내 결정 필요에이전트마다 1
작업 보고코드 → 코디네이터 검토report_work 를 남김. 코디네이터가 verified 로 확인하면 닫힘확인 필요안 셈
판정: review질문 찾기 / 코디네이터에이전트가 끝났다고 하거나 확인할 결과를 냄확인 필요안 셈
진행한 결정코드record_decision 이 멈춤 규칙에 안 걸림확인 필요안 셈
판정: idle질문 찾기 / 코디네이터사람이 할 일 없음안 보임—

우선순위: 기계 신호 카드가 있는 세션은 판정하지 않습니다. 판정은 기계 신호가 놓친 틈만 메웁니다.

5핵심 규칙

결정이 멈추는 조건 (하나라도)

  • 종류가 범위 · 데이터 구조 · 인터페이스 · 사용자에게 보임
  • 되돌리기 쉽지 않음 (costly · irreversible)
  • 확인하지 않은 가정에 기댐

의존성 · 구현 방식이면서 쉽고 가정 없음 → 진행

판정을 남길 수 있는 세션

  • 지켜보는 프로젝트의 사람이 보는 세션
  • 쉬는 중 (idle)
  • 권한·질문 창·에러·멈춘 결정·열린 보고가 없음
  • 읽은 뒤 대화가 안 바뀜 (대화 지문 비교)

사실 대답 (코디네이터만)

  • 사람이 누른 다이제스트의 주기 id · 60분 안
  • 그 주기에서 세션마다 한 번
  • 어느 브랜치, 어느 파일, PR 상태 같은 사실만
  • "결정이 아니라 정보"라고 표시해서 보냄

카드가 내려가는 때

  • 판정: 그 에이전트의 다음 턴이 끝남 · 답장/내리기/확인함
  • 보고: verified 또는 사람이 확인함
  • 에이전트·워크스페이스 archive → 관련 카드 정리

사이드바 숫자

  • 내 결정 필요만 셈 (멈춘 결정·에러·question 은 에이전트마다 1, 권한은 요청마다 1)
  • 확인 필요는 세지 않음

설정

  • 지켜볼 프로젝트 (비면 아무것도 안 바꿈)
  • 요약 켜기/끄기 · 요약 모델 (haiku)
  • 코디네이터 모델 (sonnet, 질문 찾기도 씀)
  • 언어 · 글자 크기
하지 않는 것 · 일 계획·분할·작업자 배정 · 승인·선택지 고르기·완료 인정 · 질문 찾기가 에이전트에게 말 걸기 · 코디네이터를 자동으로 깨우기 · PR 머지 · 브랜치 삭제 · 사용자 워크스페이스 archive

판정은 모델이 하므로 틀릴 수 있습니다(안 물었는데 카드, 물었는데 놓침). 확실한 것은 기계 신호 카드입니다.

6용어

지켜보는 프로젝트
설정에서 고른 프로젝트. 여기 에이전트에만 도구·지침이 붙고 판정 대상이 됨
카드
인박스에 뜨는 사람의 할 일 한 장
기계 신호
권한 요청, 질문 창, 에러, record_decision, report_work 처럼 코드가 확실히 알 수 있는 것
멈춘 / 진행한 결정
사람이 정해야 해서 기다리는 결정 / 기록하고 계속한 결정
판정
질문 찾기나 코디네이터가 세션마다 남기는 결론: question(내 답 필요) · review(확인할 결과) · idle(할 일 없음)
추천 답장
question 카드에 미리 들어 있는 답장 초안. 고쳐서 보내며, 보내는 글은 사람의 말로 그대로 감
다이제스트
사람이 누르는 한 번의 점검. 보고 검토 + 놓친 세션 판정 + 사실 대답
주기 (cycleId)
다이제스트마다 새로 만드는 id. 사실 대답은 이 안에서만
대화 지문
읽은 대화로 만든 짧은 해시. 판정할 때 대화가 바뀌었으면 거절하는 데 씀
작업 보고
워커가 report_work 로 남기는 완료·막힘 보고
outbox
에이전트에게 보낼 메시지 대기열. 쉴 때만 내보냄
자세한 설계는 DESIGN.md, 에이전트 규칙은 RULES.md 를 보세요.
